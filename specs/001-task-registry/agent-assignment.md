# Завдання агенту для програмування (Coding Agent Assignment)

**Контекст:** Реалізація HTTP-сервісу реєстру задач за специфікацією `specs/001-task-registry/spec.md`.  
**Замовник завдання:** Product Manager (PM).  
**Виконавець:** Агент для програмування (AI Coding Agent).  

---

## 1. Мета та очікуваний результат
Реалізувати локальний HTTP-сервіс на FastAPI, який відповідає всім критеріям приймання AC-1 – AC-5 зі специфікації `spec.md`, дотримуючись конституції проєкту `constitution.md`.

---

## 2. Дозволений обсяг змін (Allowed Scope)
- Створення коду сервісу у пакеті `app/` (`models.py`, `storage.py`, `policy.py`, `proposer.py`, `service.py`, `main.py`).
- Створення автоматичних тестів у `tests/` (`conftest.py`, `test_storage.py`, `test_policy.py`, `test_service.py`, `test_api.py`, `test_mutation.py`).
- Створення та виконання перевірочного notebook `notebooks/02_api_verification.ipynb`.
- Заборонено змінювати узгоджені HTTP-контракти та схеми даних без узгодження з PM.

---

## 3. Обов'язковий робочий процес (SDD Workflow)
1. **Уточнення (Clarification):** Прочитати специфікацію, виявити потенційні технічні прогалини та поставити запитання PM.
2. **Технічний план (Plan):** Підготувати `plan.md` із описом компонентів, схем та взаємодій.
3. **Задачі (Tasks):** Розбити роботу на атомарні кроки в `tasks.md`, де тести створюються раніше або паралельно з кодом (Test-First).
4. **Реалізація (Implementation):** Написати мінімально необхідний чистий код, що задовольняє тести.
5. **Перевірка (Verification):** Запустити тести pytest, провести мутаційне тестування, виконати незалежну HTTP-перевірку запущеного API.

---

## 4. Тригери обов'язкової зупинки (Stop Triggers)
Агент зобов'язаний негайно зупинити автономну генерацію та звернутися до PM у таких випадках:
1. **Неоднозначність вимоги:** Якщо вимога допускає подвійне тлумачення щодо обробки даних чи статус-кодів.
2. **Зміна контракту:** Якщо виникає спокуса змінити поля моделі `Task` або форму відповіді ендпоінтів.
3. **Нова зовнішня залежність:** Якщо агент планує додати сторонній пакет, якого немає в `pyproject.toml`.
4. **Вихід за Scope:** Пропозиції додати авторизацію, графічний інтерфейс, хмарну базу чи розсилку повідомлень.
5. **Платний API маршрут:** Спроба за замовчуванням використати платний виклик або змінити ліміти витрат.

---

## 5. Діалог PM та Агента (Уточнення та пропозиції)

### Питання агента до PM:
1. **Агент:** *«Яке сховище використати: локальний файл JSON чи тимчасову базу SQLite?»*  
   - **Відповідь PM:** Використати локальне сховище у форматі JSON з можливістю конфігурації шляху через змінну `TASK_STORE_PATH`. Для тестів має бути передбачена ізоляція сховища (окремий тестовий файл або in-memory режим).

2. **Агент:** *«Як реалізувати виклик моделі в автоматичних тестах, щоб не витрачати кошти й не залежати від наявності інтернету?»*  
   - **Відповідь PM:** Реалізувати інтерфейс `Proposer` із двома реалізаціями: `MockProposer` (детерміновані сценарії для тестів) та `OpenAIProposer` (живий виклик за наявності ключа). За замовчуванням у тестовому середовищі використовується детермінований режим.

### Розгляд технічної пропозиції агента:
- **Пропозиція агента:** *«Пропоную автоматично нормалізувати ім'я відповідального (видаляти префікси, зайві пробіли та переводити у Title Case: наприклад, "ірина" -> "Ірина").»*
- **Рішення PM щодо пропозиції:** **ПРИЙНЯТО з уточненням.**  
  *Обґрунтування:* Дозволити нормалізацію пробілів та приведення регістру імені, але зберегти суворий Grounding Check: базова основа імені обов'язково повинна міститися у вхідному тексті. Якщо у тексті немає співпадіння кореня імені — вважати галюцинацією і відхиляти.
